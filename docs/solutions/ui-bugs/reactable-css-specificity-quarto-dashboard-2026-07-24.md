# CSS specificity battle with reactable tables in Quarto dashboard

## Problem

Reactable tables in a Quarto HTML dashboard displayed wrong font sizes and persistent horizontal scrollbars across all three tabs. Five CSS-only attempts to fix the font size and three rounds of overflow debugging failed before the root causes were identified and a structural solution was adopted.

## Symptoms

- Table cell and header text rendered at the wrong size (browser default or `0.75rem`) rather than the intended `11px`, even with `!important` rules in the stylesheet.
- A horizontal scrollbar appeared on every tab, forcing the user to scroll right to see full table content.
- Both problems persisted after multiple CSS edits, giving the impression the rules were being ignored entirely.
- (session history) CSS selectors targeting `.reactable` (lowercase) had zero effect because reactable's rendered DOM uses `.Reactable` (capital R) as the outer wrapper class.

## What Didn't Work

### Font size (5 failed CSS-only attempts)

Attempts 1-5 targeted `.rt-thead .rt-th`, `.rt-td-inner`, and similar selectors with `!important`, using `0.75rem` values. All failed because CSS `!important` in a stylesheet *does* override inline styles (contrary to the common belief that inline styles always win). The CSS was winning, but it was overriding to `0.75rem` while `reactableTheme()` injected a different pixel value via inline `style=""` attributes. The rem-vs-px mismatch was the core confusion.

### Horizontal scrollbar (3+ rounds)

- **Round 1:** Set `.reactable { overflow-x: visible }`. Failed because `.rt-table` (a child element generated by reactable) still had its own `overflow: auto` default.
- **Round 2:** Added override for `.rt-table { overflow-x: visible }`. Failed because `.cell-output-display` (Quarto's wrapper around code chunk output) also had `overflow-x: auto`.
- **Round 3:** Overrode `.cell-output-display` as well. Scrollbar disappeared, but `min-width: 1700px` (later 1500px, then 1280px) on `.rt-table` forced content wider than the `max-width: 1320px` container. The real problem was geometry, not overflow settings.

### Earlier CSS selector mismatch (session history)

In a prior session, an entire round of CSS fixes (background colors, nowrap, hover states) was committed and pushed but had zero effect. The root cause: `dashboard.css` targeted `.reactable` (lowercase) but reactable's rendered HTML uses `.Reactable` (capital R). This was not caught until the user forced re-inspection of the rendered output.

### Source-code-only verification (session history)

Twice in this arc, fixes were declared "done" by reading `.qmd`/`.R` source, and were wrong — the rendered HTML/SVG showed stale or unapplied styles. Both times the user had to explicitly force verification against rendered output before the real bug was found.

## Solution

### Fix 1 — Font size: belt-and-suspenders (match inline + CSS)

Set the same `11px` value in both the R-side `reactableTheme()` (which generates inline styles) and the CSS stylesheet:

**R code** (all three tables in `dashboard.qmd`):
```r
theme = reactableTheme(
  cellPadding = "3px 5px",
  cellStyle   = list(fontSize = "11px", padding = "3px 5px"),
  headerStyle = list(fontSize = "11px", padding = "3px 5px"),
  style       = list(fontSize = "11px")
)
```

**CSS** (`dashboard.css`):
```css
.rt-thead .rt-th { font-size: 11px !important; padding: 3px 5px !important; }
.rt-tbody .rt-td { font-size: 11px !important; padding: 3px 5px !important; }
.rt-th-inner, .rt-td-inner { font-size: 11px !important; }
```

### Fix 2 — Scrollbar: wide-table-container breakout

Stopped fighting overflow on nested wrappers. Created a `.wide-table-container` class that breaks out of the content column using a centering transform:

**CSS** (`dashboard.css`):
```css
.wide-table-container {
  width: 1400px;
  max-width: 1400px;
  margin-left: 50%;
  transform: translateX(-50%);
  overflow: visible;
  border: 1px solid #d9d9d9;
  border-radius: 6px;
  background-color: #ffffff;
  padding: 16px;
  box-sizing: border-box;
}
.wide-table-container .reactable,
.wide-table-container .rt-table,
.wide-table-container .cell-output-display {
  width: 100% !important;
  min-width: 0 !important;
  overflow: visible !important;
}
```

**Quarto markup** (`dashboard.qmd`, repeated for each tab):
```markdown
::: {.wide-table-container}

```{r}
# reactable(...) call here
```

:::
```

### Fix 3 — Selector coverage

Target both `.reactable` (lowercase) and `.Reactable` (capital R) in CSS rules, plus bare `.rt-*` selectors, to ensure rules match regardless of wrapper class casing:

```css
.reactable .rt-thead .rt-th,
.Reactable .rt-thead .rt-th,
.rt-thead .rt-th {
  /* styles here */
}
```

## Why This Works

**Font size:** `reactableTheme(cellStyle=...)` generates inline `style="font-size: ..."` on every `<td>` and `<th>`. A CSS rule with `!important` overrides inline styles per the CSS cascade spec. The specificity order is: normal declarations < inline `style=""` < `!important` in stylesheet < `!important` inline. Setting both sources to the same `11px` value means the rendered size is identical regardless of which wins.

**Scrollbar:** The root cause was a geometry problem, not an overflow problem. The table's intrinsic width exceeded the dashboard's `max-width: 1320px` content column. The `.wide-table-container` gives the table a 1400px-wide box centered via `margin-left: 50%; transform: translateX(-50%)`. The table fills its container naturally with no min-width hacks and no overflow to fight.

**Selectors:** Reactable's rendered DOM uses `.Reactable` (capital R) as the outer wrapper class. CSS targeting only lowercase `.reactable` silently misses. Targeting both variants plus bare `.rt-*` selectors ensures coverage.

## Prevention

1. **When using reactable (or any JS widget that generates inline styles), always set style values in both the widget theme AND the external CSS, using the same unit (px, not rem).**

2. **For wide tables in Quarto, use the breakout-container pattern instead of fighting overflow on nested wrappers.** When a table needs more width than the prose column, wrap it in `.wide-table-container` and set `min-width: 0` on all children. Do not set `min-width` on `.rt-table` and then try to fix scrollbars with overflow toggles.

3. **Before debugging CSS overrides on a JS widget, inspect the rendered DOM first.** Run the render, open DevTools, check what inline styles the widget generates. Write CSS that matches (not conflicts with) those values. (session history) This avoids the multi-round "change CSS, re-render, still wrong" loop that occurred twice in this arc.

4. **Target multiple selector variants for reactable CSS.** Always include `.reactable`, `.Reactable`, and bare `.rt-*` selectors. The library's rendered markup does not consistently match expected class names.

5. **Know the cascade: `!important` in a stylesheet beats a regular inline style.** The common belief that "inline styles always win" is wrong. This means CSS `!important` rules will silently replace values set by `reactableTheme()`.
